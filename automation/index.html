01Интеграции и AI

От статуса задачи до PR, AI-ревью и уведомлений

Связал ClickUp, GitHub и Discord через n8n. Изменение в задаче запускает нужный сценарий: найти ветку, открыть PR, подлить master или передать изменения AI-агенту на проверку.

  1. ClickUpСтатус или чекбокс
  2. n8nУсловия и контекст
  3. GitHub + AIВетки, PR и проверка
  4. DiscordРезультат для команды

С чем столкнулся

Между разработкой, ревью и QA было много ручных действий. Нужно было искать ветки, создавать PR, напоминать о проверке и следить, чтобы задача не потерялась между сервисами.

Что сделал

Разложил процесс на сценарии n8n. Добавил поиск веток, работу с PR и шаблонами задач, правила уведомлений. Для Review подключил Python-агент: он забирает задание, читает diff и контекст проекта, запускает Codex CLI и возвращает замечания.

Что получилось

Рутинные действия запускаются из задачи. Команда получает результат в GitHub и Discord, а конфликты и ошибки обрабатываются отдельно. Каналы, роли и соответствия пользователей меняются в общих таблицах.

Что происходит при разных событиях

Merge — ожидание и повторная проверка статуса перед созданием PR. Testing или чекбокс — подлив master в рабочую ветку с отдельной обработкой конфликтов. Rejected и Closed — уведомление нужного канала и ответственных. BUG и REPEAT — подстановка шаблона описания.

Для AI-ревью n8n подготавливает задание в GitHub, а Python-poller забирает его по меткам PR. У задания есть состояния, повторы при сетевых ошибках и восстановление прерванной работы. Проверка выполняется через Codex CLI; итоговое решение по коду остаётся за командой.

При сопровождении разбирал всю цепочку: доставка вебхука, фильтры, поиск данных и внешнее действие. Добавлял проверку подписей и защиту от повторной обработки событий.

03Сборки и доставка

От готовой сборки до ссылки на скачивание

Связал TeamCity, объектное хранилище, n8n и Discord. Развивал портал, на котором команда может найти сборку и запустить нужное действие.

  1. TeamCityСборка и архив
  2. R2 / S3 APIЗагрузка и checksum
  3. n8nПортал и действия
  4. DiscordОтчёт о сборке

С чем столкнулся

Команде нужен был единый способ получить билд, понять его состояние и выбрать архив для публикации. При скачивании больших архивов приходилось разбираться с обрывами и повреждёнными файлами.

Что сделал

Занимался загрузкой архивов, подписанными ссылками, поиском по хранилищу, уведомлениями и запуском Steam deploy через TeamCity. Добавил повторы скачивания, временные файлы и проверки контрольной суммы и целостности архива.

Что получилось

Доставка сборок стала связным процессом с порталом и уведомлениями. Проблему со скачиванием можно обнаружить до распаковки и запуска SteamCMD, а не искать её уже после неудачной публикации.

Возможности портала и проверки архивов

Сценарии портала включают просмотр и поиск архивов, ссылки скачивания, заметки и правила хранения. Dashboard связан с TeamCity: можно выбрать ветку, поставить сборку в очередь, отменить её и посмотреть историю.

В цепочку доставки добавил SHA-256 в метаданных, скачивание во временный файл и проверку архива перед публикацией. Размещение перенесённого портала на постоянном собственном домене — отдельный этап, который ещё готовится.

04Мониторинг и обслуживание

Состояние билдмашины и команды для сервисов

Разработал сценарий watchdog для билдмашин: приём heartbeat, определение доступности и очередь команд для сервисов TeamCity.

  1. БилдмашинаHeartbeat и состояние
  2. n8nВремя последнего сигнала
  3. DashboardДоступность машины
  4. ОчередьКоманда и подтверждение

С чем столкнулся

Нужно было отличать зависшую сборку от недоступной машины и иметь способ управлять сервисами, не подключаясь каждый раз к рабочему столу.

Что сделал

Сценарий сохраняет heartbeat и время его получения, а по возрасту сигнала определяет доступность. Для сервисов сделал очередь команд start и restart с подтверждением выполнения.

Что получилось

Есть отдельный источник состояния машины и понятный путь команды: постановка, ожидание, подтверждение или истечение срока. Потерянная команда не должна выполняться спустя неопределённое время.

Очередь команд и ограничения

В сценарии для BM192 машина считается доступной, если heartbeat получен не более 90 секунд назад. Команды разрешены только для заданного списка сервисов TeamCity и агентов. У команды есть ID и срок действия; следующая не принимается, пока предыдущая ещё ожидает выполнения.

Машина получает команду в ответе на heartbeat и подтверждает её по ID. Просроченные команды снимаются с ожидания. Так в обработчике есть контроль состояния, а не просто вызов перезапуска сервиса.

05Внутренний инструмент

Automation Hub — сервис для сценариев команды

Параллельно со сценариями n8n разрабатывал внутренний сервис с визуальным редактором, версиями сценариев, историей запусков и таблицами настроек.

  1. РедакторReact + TypeScript
  2. ВыполнениеASP.NET Core + Elsa
  3. СостояниеPostgreSQL
  4. ИнтеграцииWebhooks + API

С чем столкнулся

Хотел управлять сценариями на своей инфраструктуре, видеть ход выполнения и использовать уже собранные автоматизации n8n.

Что сделал

Сделал редактор и backend, импорт используемых узлов n8n, публикацию версий и просмотр данных запуска. Перенёс общие справочники в Data Tables и добавил вход по паролю.

Что получилось

Сервис запускается на билдмашине. Сценарии, настройки и история хранятся в базе. Перенёс существующие сценарии и по мере проверки дорабатывал интеграции и развёртывание.

Что входит в сервис и его границы

Реализованы ветвления, настраиваемые ожидания, неизменяемые опубликованные версии, входы и выходы узлов, таблицы и отдельные приёмники событий. Импорт рассчитан на узлы наших сценариев, а не на полную совместимость со всеми возможностями n8n.

Также подготовил скрипты установки, переноса, диагностики и автозапуска. Сквозная проверка идёт по отдельным сценариям: сам импорт графа ещё не означает, что все внешние действия проверены.
