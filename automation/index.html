01AI-проверка кода

От задачи в Review до замечаний по коду

Связал ClickUp, n8n, GitHub и Python-агент, чтобы при переходе задачи в Review запускалась AI-проверка связанных с ней изменений.

  1. ClickUpСтатус Review
  2. n8nПроверки и контекст
  3. GitHubPR и очередь
  4. Python + CodexРевью и замечания

С чем столкнулся

Для ревью приходилось отдельно находить ветку задачи, открывать PR, собирать контекст и передавать результат команде.

Что сделал

Сценарий проверяет задачу и ветку, находит или создаёт PR и ставит задание в очередь. Агент читает diff, собирает контекст проекта и запускает Codex CLI. Замечания отправляются в GitHub и Discord.

Что получилось

У проверки появился понятный путь от задачи до замечаний и состояния, по которым видно, ждёт она запуска, выполняется или завершилась ошибкой. Решение по коду по-прежнему принимает команда.

Как устроена интеграция

n8n обрабатывает событие, фильтрует задачи и подготавливает задание в GitHub. Отдельный Python-poller забирает задания по меткам PR. LLM подключена через Codex CLI.

У агента есть состояния задания, повторные попытки при сетевых ошибках и логика восстановления прерванной работы. Уведомление о постановке в очередь и завершённое ревью — разные этапы.

  • n8n
  • Python
  • JavaScript
  • Codex CLI
  • GitHub API
  • ClickUp API
02Процессы команды

Задачи, ветки и уведомления в одной цепочке

Собрал и доработал n8n-сценарии, которые реагируют на события ClickUp, выполняют нужное действие в GitHub и уведомляют ответственных в Discord.

  1. ClickUpСтатус или чекбокс
  2. n8nУсловия и справочники
  3. GitHubВетки и PR
  4. DiscordУведомление команды

С чем столкнулся

За изменением задачи шли повторяющиеся действия: найти ветку, открыть PR, подлить master и сообщить следующему участнику, что произошло.

Что сделал

Связал поиск ветки, создание PR, синхронизацию веток, шаблоны задач и уведомления. Каналы, роли и соответствия пользователей вынес в таблицы, чтобы не менять их отдельно в каждом сценарии.

Что получилось

Событие в задаче может запускать следующий шаг без отдельной ручной передачи. Ошибки и конфликты слияния идут по своим веткам и сообщают о себе тем, кто должен разобраться.

Примеры сценариев и обработка ошибок
  • Статус Merge: подождать, повторно проверить статус задачи и только потом создать PR.
  • Статус Testing или чекбокс: подлить master в ветку задачи, отдельно обработать конфликт.
  • Статус Rejected или Closed: выбрать канал и упоминания по настроенным правилам.
  • Новая задача BUG или REPEAT: при необходимости подставить шаблон описания.

Отдельно занимался маршрутизацией и диагностикой вебхуков: отличал недоставленное событие от ошибки внутри сценария, проверял подписи и защиту от повторной обработки.

  • n8n

03Сборки и доставка

От готовой сборки до ссылки на скачивание

Связал TeamCity, объектное хранилище, n8n и Discord. Развивал портал, на котором команда может найти сборку и запустить нужное действие.

  1. TeamCityСборка и архив
  2. R2 / S3 APIЗагрузка и checksum
  3. n8nПортал и действия
  4. DiscordОтчёт о сборке

С чем столкнулся

Команде нужен был единый способ получить билд, понять его состояние и выбрать архив для публикации. При скачивании больших архивов приходилось разбираться с обрывами и повреждёнными файлами.

Что сделал

Занимался загрузкой архивов, подписанными ссылками, поиском по хранилищу, уведомлениями и запуском Steam deploy через TeamCity. Добавил повторы скачивания, временные файлы и проверки контрольной суммы и целостности архива.

Что получилось

Доставка сборок стала связным процессом с порталом и уведомлениями. Проблему со скачиванием можно обнаружить до распаковки и запуска SteamCMD, а не искать её уже после неудачной публикации.

Возможности портала и проверки архивов

Сценарии портала включают просмотр и поиск архивов, ссылки скачивания, заметки и правила хранения. Dashboard связан с TeamCity: можно выбрать ветку, поставить сборку в очередь, отменить её и посмотреть историю.

В цепочку доставки добавил SHA-256 в метаданных, скачивание во временный файл и проверку архива перед публикацией. Размещение перенесённого портала на постоянном собственном домене — отдельный этап, который ещё готовится.

  • TeamCity
  • n8n
  • PowerShell
  • Cloudflare R2
  • S3 API
  • SteamCMD
04Внутренний инструмент

Automation Hub — сервис для сценариев команды

Параллельно со сценариями n8n разрабатывал внутренний сервис с визуальным редактором, версиями сценариев, историей запусков и таблицами настроек.

  1. РедакторReact + TypeScript
  2. ВыполнениеASP.NET Core + Elsa
  3. СостояниеPostgreSQL
  4. ИнтеграцииWebhooks + API

С чем столкнулся

Хотел управлять сценариями на своей инфраструктуре, видеть ход выполнения и использовать уже собранные автоматизации n8n.

Что сделал

Сделал редактор и backend, импорт используемых узлов n8n, публикацию версий и просмотр данных запуска. Перенёс общие справочники в Data Tables и добавил вход по паролю.

Что получилось

Сервис запускается на билдмашине. Сценарии, настройки и история хранятся в базе. Перенёс существующие сценарии и по мере проверки дорабатывал интеграции и развёртывание.

Что входит в сервис и его границы

Реализованы ветвления, настраиваемые ожидания, неизменяемые опубликованные версии, входы и выходы узлов, таблицы и отдельные приёмники событий. Импорт рассчитан на узлы наших сценариев, а не на полную совместимость со всеми возможностями n8n.

Также подготовил скрипты установки, переноса, диагностики и автозапуска. Сквозная проверка идёт по отдельным сценариям: сам импорт графа ещё не означает, что все внешние действия проверены.

  • C# / .NET
  • ASP.NET Core
  • React
  • TypeScript
  • PostgreSQL
  • Elsa
